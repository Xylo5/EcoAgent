================================================================================
GRID SYSTEM (GridManager.cs)
================================================================================
Grid: 100x100 cells
Cell size: 2.5 (forced in Awake(), may be 0 in edit mode)
Grid world extent: (0, 0, 0) to (250, 0, 250)

GridOrigin Calculation:
  offsetX = (terrainData.size.x - gridWidth * cellSize) * 0.5 = (350-250)*0.5 = 50
  offsetZ = (terrainData.size.z - gridHeight * cellSize) * 0.5 = (350-250)*0.5 = 50
  GridOrigin = terrainPos + (offsetX, 0, offsetZ) = (-50+50, 0, -50+50) = (0, 0, 0)

GridOrigin property has edit-mode fallback: uses cellSize 2.5 if serialized is 0.
Auto-finds Terrain in edit mode if not assigned.

Cell Occupancy:
  occupiedCells[,]  — buildings, temporary. Freed by FreeCells()
  permanentCells[,] — roads, environment. Never freed by FreeCells()
  Both arrays initialized in Awake() — NULL in edit mode
  OccupyCellsPermanent() must only be called at runtime (guard with Application.isPlaying)

Manual Placement Scanning:
  GridManager.Start() calls MarkManualPlacementsAtRuntime():
    - Scans manualPlacementParents[] (inspector array of parent Transforms)
    - Auto-finds GameObject named "ManualBuildings" if array is not assigned
    - For each child under each parent: computes combined Renderer.bounds
    - Converts bounds to grid cell range (Floor/Ceil) and marks cells permanent
    - Ensures manually placed scene prefabs block the grid at runtime
    - Logs per-object details: name, bounds, cell range
  Usage: Create an empty "ManualBuildings" GameObject in the scene,
         parent any manually placed building prefabs under it.
         No inspector assignment needed — auto-discovered by name.

Edit Mode Gotchas:
  cellSize is 0 until Awake runs -> always use fallback: cellSize > 0 ? cellSize : 2.5f
  terrain field may be null if not Inspector-assigned -> use Terrain.activeTerrain fallback
  occupiedCells/permanentCells are null -> skip OccupyCellsPermanent calls
  GridOrigin property handles all these internally with fallbacks

Key Methods:
  GetCellWorldCenter(cell)          — Single cell center in world space
  SnapToGrid(worldPos, size)        — Snap world pos to nearest cell
  SnapToGrid(worldPos, sizeX, sizeZ)— Rectangular snap overload
  WorldToGrid(worldPos)             — World -> grid cell
  IsAreaAvailable(cell, size)       — Check if cells are free (square)
  IsAreaAvailable(cell, sizeX, sizeZ)— Check if cells are free (rectangular)
  OccupyCells(cell, size)           — Mark cells occupied (temporary, square)
  OccupyCells(cell, sizeX, sizeZ)   — Mark cells occupied (temporary, rectangular)
  FreeCells(cell, size)             — Free cells (skips permanent)
  FreeCells(cell, sizeX, sizeZ)     — Free cells (rectangular, skips permanent)
  OccupyCellsPermanent(cell, size)  — Mark cells permanent (square, delegates to rectangular)
  OccupyCellsPermanent(cell, sizeX, sizeZ) — Mark cells permanent (rectangular)
  IsCellPermanent(cell)             — Check if permanently blocked
  MarkManualPlacementsAtRuntime()   — Scans ManualBuildings children, marks permanent

World Position Formula (used by BuildingPlacer, RoadGenerator):
  x = GridOrigin.x + cell.x * cellSize + (size * cellSize) / 2
  z = GridOrigin.z + cell.y * cellSize + (size * cellSize) / 2
  y = terrain.SampleHeight(x, z) + terrain.position.y

================================================================================
BORDER FOREST (BorderForestSpawner.cs)
================================================================================
Spawns decorative trees in the terrain area OUTSIDE the playable grid.
Border width: (terrainSize - gridSize) / (2 * cellSize) = (350-250)/(2*2.5) = 20 cells
Trees are placed in 20-cell-wide strips on all 4 sides.
Trees skip cells inside the grid area.
Road borderMargin of 2 cells keeps roads 1 block from grid edge.

Coordinate Map:
  Terrain: (-50,0,-50) to (300,0,300)
    |  20-cell tree border on all sides  |
    |  Grid: (0,0,0) to (250,0,250)     |
    |    Road area: cell(2,2)-(97,97)    |
    |    with borderMargin=2             |

================================================================================
ROAD GENERATION SYSTEM (RoadGenerator.cs)
================================================================================
Generates straight-line road network creating city blocks.
Attached to a GameObject in the scene with GridManager reference.

INSPECTOR FIELDS:
  gridManager         GridManager    required    Reference to grid system
  roadStart           CityTileData   required    Dead-end start tile
  roadEnd             CityTileData   required    Dead-end end tile
  roadFiller1-5       CityTileData   required    Straight road segments
  roadIntersection    CityTileData   required    4-way crossing
  roadBranch          CityTileData   required    T-junction / corners
  emptySpace          CityTileData   required    Non-blocking fill tile
  generateRiver       bool           false       Toggle river generation
  riverDirection      RiverDirection Random      Random / NorthSouth / EastWest
  riverPrefab         GameObject     null        Optional custom prefab for river visuals (auto-scaled)
  generateMountains   bool           false       Toggle mountain generation
  mountainCount       int            1           Range 0-5, number of 20x20 mountains
  mountainPrefab      GameObject     null        Optional custom prefab for mountain visuals (auto-scaled)
  horizontalRoads     int            5           Range 3-12
  verticalRoads       int            5           Range 3-12
  roadJitter          int            1           Range 0-2, subtle block size variation
  borderMargin        int            2           Cells from grid edge (1 block = 2 cells)
  randomSeed          int            0           0 = random each run
  fillEmptySpace      bool           true        Fill non-road areas
  debugYOffset        float          0.15        Extra Y above terrain
  lastComputedScale   float          readonly    Shows uniform scale applied to all tiles

SCENE-VIEW-ONLY GENERATION:
  RoadGenerator does NOT auto-generate at runtime (no generateOnStart).
  Generation is done in Scene view via the Editor "Generate All" button.
  At runtime, Start() calls MarkExistingObstaclesAtRuntime() instead:
    - Scans all children by Renderer.bounds
    - Skips empty space filler tiles (non-blocking, identified by emptySpace.tileName prefix)
    - Converts bounds to grid cell ranges and calls OccupyCellsPermanent() per cell
    - This ensures roads/rivers/mountains block the grid without regenerating

GENERATION FLOW (Editor / Scene view only):
  1. CacheGridSettings() — reads gridWidth, gridHeight, cellSize from GridManager
  2. ClearMap() — destroys all children
  3. InitGrids() — creates roadMap, placedMap, and obstacleMap bool arrays
  4. GenerateRiver() — (if enabled) places 6-cell-wide straight river edge-to-edge, marks obstacleMap
  5. GenerateMountains() — (if enabled) places N 20x20 mountains at random positions avoiding obstacles
  6. GenerateRoadNetwork() — paints straight horizontal/vertical roads on roadMap (skips obstacle cells)
  7. ComputeReferenceScale() — measures filler1 bounds, computes uniform scale for all tiles
  8. InstantiateRoadTiles() — classifies 2x2 blocks by neighbor count, picks tile + rotation
  9. FillEmptySpace() — fills non-road, non-obstacle cells with emptySpace (no grid blocking)

ROAD CLASSIFICATION (by neighbor count):
  0 neighbors -> roadStart, rotation 0
  1 neighbor  -> roadStart (near edge) or roadEnd
                 Rotation: hasN=270, hasE=0, hasS=90, hasW=180
  2 straight  -> random filler, rotation: E-W=90, N-S=0
  2 corner    -> roadBranch: N+E=0, E+S=90, S+W=180, N+W=270
  3 neighbors -> roadBranch (T-junction): !S=0, !W=90, !N=180, !E=270
  4 neighbors -> roadIntersection, rotation 0

TILE INSTANTIATION (InstantiateTile):
  1. Always uses Instantiate() (never PrefabUtility) so children can be modified
  2. Computes world position via GetWorldPosition() (GridOrigin + cell offset + terrain height)
  3. Applies uniform referenceScale (from filler1) to all tiles
  4. Bounds-based centering: computes Renderer.bounds center offset, shifts root position
  5. Sets layer to "Ignore Raycast"
  6. Calls OccupyCellsPermanent() for road tiles at runtime only

SCALING SYSTEM:
  ComputeReferenceScale() instantiates filler1 temporarily, measures its Renderer.bounds
  Computes: referenceScale = (2 * cellSize) / maxBoundsSize
  This same scale is applied to ALL road tile types (uniform appearance)
  LogPrefabScales() logs each prefab's native size + computed scale to Console

FILLER WEIGHTING:
  Filler1: weight 3 (~33%)
  Filler2: weight 3 (~33%)
  Filler3-5: weight 1 each (~11%)

ROAD NETWORK LAYOUT:
  Roads are evenly spaced within the border margin
  Slight random jitter (+-roadJitter blocks) for natural block variation
  ~15% chance inner roads get trimmed (end early) from one side
  First/last roads always span full region
  roadStart tiles biased to IsNearEdge (borderMargin + 6 cells from edge)

WORLD POSITION (GetWorldPosition):
  x = GridOrigin.x + cell.x * cellSize + (size * cellSize) * 0.5
  z = GridOrigin.z + cell.y * cellSize + (size * cellSize) * 0.5
  y = max(terrain height at 5 sample points) + terrain.position.y + debugYOffset
  5-point sampling: center + 4 corners (prevents terrain clipping on slopes)
  Falls back to Terrain.activeTerrain if gridManager.terrain is null (edit mode)
  Matches BuildingPlacer.GridCellToWorldPos formula exactly

================================================================================
ENVIRONMENT GENERATION (River & Mountains)
================================================================================
Generated BEFORE roads. Both mark obstacleMap[,] — roads skip obstacle cells entirely.
PaintBlock() checks all 4 cells in a 2x2 block; if any is an obstacle, the whole block is skipped.
FillEmptySpace() also skips obstacle cells.

RIVER:
  Direction: RiverDirection enum (Random, NorthSouth, EastWest)
  Width: 6 cells, spans full grid edge-to-edge
  NorthSouth: 6 cells wide in X, full gridHeight in Z
  EastWest: full gridWidth in X, 6 cells wide in Z
  Position: random within borderMargin constraints
  Visual (riverPrefab = null): runtime-generated blue semi-transparent Cube primitive (URP Lit, transparent)
  Visual (riverPrefab assigned): single instance, auto-scaled to fit river area via bounds measurement
    - Measures Renderer.bounds of instantiated prefab
    - Computes scaleX = targetWidth / nativeWidth, scaleZ = targetHeight / nativeHeight
    - Multiplies against prefab's original localScale (not replacing it)
    - Bounds-based centering applied after scaling
  Collider removed. Layer set to "Ignore Raycast"
  Cells marked in obstacleMap + placedMap. Marked permanent at runtime via OccupyCellsPermanent()

MOUNTAINS:
  Count: configurable (0-5), default 1
  Size: 20x20 cells each
  Position: random within borderMargin, must not overlap existing obstacles (river or other mountains)
  Placement: up to 100 random attempts per mountain; logs warning if no valid position found
  Visual (mountainPrefab = null): runtime-generated brown Cube primitive (URP Lit, opaque), scaled to worldSize with 0.5x height
  Visual (mountainPrefab assigned): single instance, auto-scaled to fit mountain 20x20 cell area
    - Measures Renderer.bounds of instantiated prefab
    - Computes scaleXZ = worldSize / max(nativeX, nativeZ), scaleY = (worldSize*0.5) / nativeY
    - Bounds-based centering applied after scaling
  Collider removed. Layer set to "Ignore Raycast"
  Cells marked in obstacleMap + placedMap. Marked permanent at runtime via OccupyCellsPermanent()

OBSTACLE AVOIDANCE ORDER:
  1. River generates first (if enabled)
  2. Mountains avoid river cells (if both enabled)
  3. Roads avoid all obstacle cells (PaintBlock skips if any cell in 2x2 is obstacle)
  4. FillEmptySpace skips obstacle cells

================================================================================
CITY GENERATION SYSTEM (CityGenerator.cs)
================================================================================
Procedurally places buildings on empty grid cells near roads.
Generation is done in Scene view via Editor button — NOT at runtime.
Attach to an empty GameObject, assign GridManager + RoadGenerator + BuildingData[].

INSPECTOR FIELDS:
  gridManager         GridManager     required    Reference to grid system
  roadGenerator       RoadGenerator   required    Reference to road generator (reads children)
  buildings           BuildingData[]  required    Array of building types to place (modular)
  randomSeed          int             0           0 = random each run
  density             int             20          Range 5-80, percentage of candidates to fill
  roadProximity       int             2           Range 1-3, cells away from road to allow placement
  debugYOffset        float           0.15        Extra Y above terrain

GENERATION ALGORITHM (Generate):
  1. CacheGridSettings()     — reads gridWidth, gridHeight, cellSize from GridManager
  2. ClearMap()              — destroys all children (previously generated buildings)
  3. InitGrids()             — creates occupiedMap[,] and roadCellMap[,] bool arrays
  4. BuildOccupiedMap()      — scans RoadGenerator children by Renderer.bounds,
                               marks their grid cells as occupied. Skips empty space
                               filler tiles (identified by emptySpace.tileName prefix)
  5. BuildRoadCellMap()      — scans RoadGenerator children (excluding River_, Mountain_,
                               and empty space fillers) by Renderer.bounds to identify
                               which grid cells contain actual road tiles
  6. FindRoadAdjacentCells() — iterates entire grid, collects cells that are:
                               (a) NOT occupied and (b) NOT road cells and
                               (c) within roadProximity cells of a road cell
  7. ShuffleList(candidates) — Fisher-Yates shuffle for random ordering
  8. SelectBuildingTypes()   — picks random subset (min 3, max all) of assigned
                               BuildingData types; different each seed
  9. Placement loop          — iterates shuffled candidates up to density% cap:
                               - picks random BuildingData from selected subset
                               - picks random rotation (0/90/180/270)
                               - swaps sizeX/sizeZ for 90/270 rotations
                               - checks bounds + IsAreaFree()
                               - calls PlaceBuilding() + MarkOccupied()

BUILDING PLACEMENT (PlaceBuilding):
  1. Compute world position: GetWorldPosition(cell, sx, sz)
     Formula: x = origin.x + cell.x * cellSize + (sx * cellSize) * 0.5
              z = origin.z + cell.y * cellSize + (sz * cellSize) * 0.5
              y = terrain.SampleHeight() + terrain.position.y + debugYOffset
  2. Instantiate prefab with rotation, parented under CityGenerator transform
  3. AutoScaleToGrid — same algorithm as BuildingPlacer:
     - Reset scale to Vector3.one
     - Measure Renderer.bounds at scale 1
     - Uniform scale = (max(targetX, targetZ) / max(boundsX, boundsZ)) * scaleMultiplier
     - targetX = data.sizeX * cellSize, targetZ = data.sizeZ * cellSize
  4. Bounds-based centering after scaling:
     - offset = (position - bounds.center) for X/Z, (position - bounds.min) for Y
     - shifts instance to center it on the target cell area with base on ground
  5. Remove colliders (DestroyImmediate in editor)
  6. Set layer to "Ignore Raycast"

BUILDING TYPE SELECTION (SelectBuildingTypes):
  - Filters null entries from the buildings[] array
  - Picks a random count between min(3, total) and total
  - Shuffles valid list, takes first 'count' entries
  - Ensures variety: each seed gets a different subset of building types

ROAD ADJACENCY DETECTION:
  Rather than coupling to RoadGenerator's internal roadMap (private, transient),
  the system scans RoadGenerator's instantiated children at generation time.
  For each child, computes covered grid cells from Renderer.bounds:
    minX = Floor((bounds.min.x - origin.x) / cellSize)
    minZ = Floor((bounds.min.z - origin.z) / cellSize)
    maxX = Ceil((bounds.max.x - origin.x) / cellSize)
    maxZ = Ceil((bounds.max.z - origin.z) / cellSize)
  Three categories of children are distinguished by name prefix:
    - "River_*" and "Mountain_*" → obstacles, marked in occupiedMap only
    - emptySpace.tileName prefix → non-blocking fillers, skipped entirely
    - Everything else            → road tiles, marked in both occupiedMap AND roadCellMap

EMPTY SPACE FILLER HANDLING:
  Critical distinction: RoadGenerator's emptySpace tiles are NON-BLOCKING.
  They fill visual gaps but players can place buildings on those cells.
  Both CityGenerator and RoadGenerator's runtime marking skip these tiles:
    - CityGenerator.BuildOccupiedMap() skips them (so buildings can be placed there)
    - CityGenerator.BuildRoadCellMap() skips them (they aren't roads)
    - RoadGenerator.MarkExistingObstaclesAtRuntime() skips them (don't block at runtime)
  Identification: child.name.StartsWith(emptySpace.tileName)

RUNTIME BEHAVIOR (Start):
  No regeneration. Start() calls MarkExistingBuildingsAtRuntime():
    - Scans all children by Renderer.bounds
    - Converts bounds to grid cell ranges
    - Calls OccupyCellsPermanent() per cell
    - Generated buildings become permanent obstacles at runtime

DENSITY CONTROL:
  maxPlacements = max(1, (candidates.Count * density) / 100)
  At density=20 with 5000 candidates, attempts up to 1000 placements.
  Not all attempts succeed (buildings may not fit), so actual count < max.
  Sparse placement is natural: large buildings consume many candidates,
  and shuffled order prevents clustering.

================================================================================
WIN/LOSE CHECK SYSTEM
================================================================================
Flow: LevelHUD (Check button) → ResultData → SceneLoader.LoadResult() → ResultUI

CHECK BUTTON (LevelHUD.cs):
  - Code-generated orange button in bottom-right corner of Level 0 HUD
  - On click: reads PollutionManager.GetPollution()
  - Win condition: pollution < 0 (player must fully offset starting pollution)
  - Sets ResultData static fields (PollutionScore, Won, LevelIndex)
  - Calls SceneLoader.LoadResult() to transition to Result scene

RESULT DATA (ResultData.cs):
  Static class for passing data between scenes (no MonoBehaviour needed):
    ResultData.PollutionScore  — int, final pollution value
    ResultData.Won             — bool, true if pollution < 0
    ResultData.LevelIndex      — int, which level was played (for retry)

RESULT SCENE (ResultUI.cs):
  Fully code-generated UI at runtime — no manual Canvas/EventSystem setup needed.
  BuildUI() creates at Start():
    - Canvas (ScreenSpaceOverlay, 1920x1080 reference)
    - EventSystem + InputSystemUIInputModule (new Input System, not StandaloneInputModule)
    - Dark background overlay
    - Center panel with:
      - Title: green "YOU WIN!" or red "YOU LOSE"
      - Score: "Pollution: N"
      - Hint: context-appropriate message
      - "Level Select" button → SceneLoader.LoadLevelSelect()
      - "Retry" button → SceneLoader.LoadLevel(ResultData.LevelIndex)
  Escape key also returns to Level Select.

SCENE LOADER (SceneLoader.cs):
  Static utility with methods:
    LoadMainMenu()      → "MainMenu"
    LoadLevelSelect()   → "LevelSelect"
    LoadLevel(index)    → "Level_N"
    LoadResult()        → "Result"

INPUT SYSTEM NOTE:
  Project uses new Input System package (not legacy UnityEngine.Input).
  UI EventSystem must use InputSystemUIInputModule, NOT StandaloneInputModule.
  StandaloneInputModule causes InvalidOperationException at runtime.
